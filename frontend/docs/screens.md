# 画面・UI部品の仕様

`frontend/lib/views/`・`widgets/`・`utils/`の各ファイルの仕様。2026-11-10時点のmainの実装を正とする。
画面の一覧と遷移は`docs/basic-design/screens.md`。収録・保存/破棄の流れは`frontend/docs/location-tracking.md`・
`frontend/docs/session-recovery.md`、認証・アカウントの状態の扱いは`frontend/docs/overview.md`の「認証とアカウント」。
全てのファイルを挙げ、画面の挙動として書くことがあるものだけ詳しく書く。

## views/

- main_page.dart: メイン画面(下のタブ: 収録・履歴・統計・設定)。全タブ共通のバナーを上部に並べる(`frontend/docs/location-tracking.md`の
  「バナーの表示」)。`initState`で未完了の収録を回収し、フォアグラウンド復帰時に位置情報の状態を確かめる
- recording_page.dart: 収録タブ
  - 上部の切り替えで「セッション情報」(経過時間・距離などと開始/停止のボタン)と「マップ操作」(`map_view.dart`)を切り替える
  - 開始中(`starting`)は、タブ全体を操作できなくして「現在地を取得しています…」と「キャンセル」を出す
  - 開始できなかったときは、ダイアログ「収録を開始できません」(「閉じる」「再試行」と`GpsHelpLinkButton`)を出す
  - 停止はダイアログ「トラッキング停止」で確かめる。保存/破棄が未確定(`stopping`)の間、開始のボタンは「前回のセッションを処理」になる
- map_view.dart: 収録タブの「マップ操作」(`MapControlTabView`)。地図を自由に動かせる
- saved_sessions.dart: 履歴タブ(保存済みセッションの一覧)
  - ★のボタンでお気に入りを切り替える
  - AppBarの「編集」で編集モードにし、「完了」で戻る。編集モードでは、項目のタップで名前・移動手段の編集ダイアログを出し、ゴミ箱のボタンで削除する
  - 編集ダイアログの「保存」で、名前が空欄(空白だけを含む)なら元の名前のまま、移動手段は選んだものに更新する(`updateSessionInfo`)
  - 右から左へのスワイプでも削除できる。削除はどちらもダイアログ「セッションを削除しますか?」で確かめる
- session_detail_view.dart: 記録の詳細画面(地図・統計・高度のグラフ)。タイトル(`SessionDetailTitle`)と本文(`SessionDetailBody`)は
  保存/破棄画面でも使う。地図の初期表示は`MapOptions.initialCameraFit`で合わせる(`frontend/docs/overview.md`の「地図 (flutter_map)」)
- save_or_discard_page.dart: 収録の停止後の保存/破棄画面(`frontend/docs/session-recovery.md`の「保存/破棄画面」)
- analytics_page.dart: 統計タブ(月・年・全期間のグラフ)
- gps_help_page.dart: GPSを掴みやすくするコツ。位置情報のバナー(未取得・更新停止)と、開始できなかったときのダイアログから開く
- settings_page.dart: 設定タブ。今はアカウントの欄だけ
  - 通常のアカウントの並び: 表示名(タップで編集ダイアログ) → メールアドレスと確認状態(未確認ならタップで確認コードの入力画面) →
    パスワードの変更 → ログアウト。区切りの下に「ローカルアカウントにする」、一番下にアカウントの削除(取り返しのつかない操作なので区切って置く)
  - ローカルアカウントの並び: 表示名 → 「ローカルアカウント」(同期しないことの説明) → アカウントの切り替え → 通常のアカウントにする、
    区切りの下にアカウントの削除。メールアドレス・パスワードの変更・ログアウトは出さない
  - 収録中は、ユーザーIDが変わる操作(ログアウト・アカウントの削除・アカウントの切り替え・通常のアカウントにする)をスナックバーで止める。
    表示名の編集・確認コードの入力・パスワードの変更・ローカルアカウントにする(ユーザーIDが変わらない)は収録中もできる
  - 「ローカルアカウントにする」は、確認ダイアログの後に同期を試み、失敗したら続けるかを聞いてから、サーバーのアカウントを削除する
- auth/login_page.dart: ログイン画面。起動時に未ログインなら出す(ログイン・新規登録のほか「ローカルアカウントで使う(同期しない)」)。
  再ログインのバナーから開いたとき(`isRelogin`)は、ログインしたら閉じて元の画面に戻る。「通常のアカウントにする」から開いたとき(`mergeLocal`)は、
  送る前に記録を移すことを確かめる
- auth/signup_page.dart: 新規登録画面。登録するとそのままログインした状態になり、確認コードの入力画面を開く。`mergeLocal`なら記録を移す
- auth/local_account_list_page.dart: ローカルアカウントの選択画面
  - 入口: ログイン画面の「ローカルアカウントで使う(同期しない)」、ローカルアカウントの設定タブの「アカウントの切り替え」
  - 端末のローカルアカウントを作った順に並べ、今のアカウントにチェックを付ける。ほかのアカウントのタップで切り替える(今のアカウントのタップは
    閉じるだけ)。「新しいローカルアカウント」で表示名を入れて作る(既定は「ローカル」)。切り替え・作成の後は、重ねた画面を全て閉じてメイン画面に戻る。
    切り替えに失敗したらスナックバー「切り替えられませんでした」
  - 設定タブから開いたときだけ「通常のアカウントでログイン」(このローカルアカウントの記録は移さずに残る)を出す
- auth/change_password_page.dart: パスワードの変更画面(設定タブから開く)
  - 入力欄は「現在のパスワード」「新しいパスワード(8〜128文字)」「新しいパスワード(確認)」。「パスワードを表示する」で3つとも見えるようにできる
  - 端末で確かめること: 未入力、新しいパスワードの長さ、確認との一致(満たさなければ送らない)
  - 現在のパスワードが違う(400 `invalid_current_password`)ときは、その欄の下に「現在のパスワードが違います」と出す
  - 試行回数の上限(429 `too_many_requests`。値は`backend/docs/auth.md`の「ログインの試行回数の制限」)のときは、`Retry-After`から
    「◯分後に」(分に切り上げ。無ければ「しばらくしてから」)もう一度試すよう出す。ログイン画面の429も同じ形で出す
  - 成功したら、スナックバー「パスワードを変更しました。他の端末はログインし直しになります」を出して閉じる(この端末はログインしたまま)
- auth/email_verification_page.dart: メールアドレスの確認コード(6桁)の入力画面
  - 入口: 新規登録の直後(自動で開く)、未確認のバナーのタップ、設定タブの確認状態の行のタップ。収録中でも開ける(同期の再開は収録を邪魔しない)
  - 表示: 「(メールアドレス) に届いた6桁のコードを入力してください」と「確認が済むまで、記録はサーバーと同期されません」。新規登録の直後に
    開いたときだけ「あとで(設定タブからも確認できます)」を出し、押すと閉じる(未確認でも記録はできる)。それ以外の入口ではAppBarの戻るで閉じる
  - 入力欄: 数字だけ・6桁まで(数字キーボード、iOSのワンタイムコードの自動入力に対応)。6桁そろうまで「確認」は押せない。6桁そろっても
    自動では送らない(打ち間違いで入力の失敗の回数を減らさないため)
  - 「コードを再発行」: 画面を開いただけでは送らない(新規登録のときに送り済みで、二重に送ると1日の送信の回数も減るため)。押せるようになるまでの
    秒数をボタンに出し(「コードを再発行(あと◯秒)」)、その間は押せない。新規登録の直後は60秒から始める。待ち時間は画面の中だけで持ち、
    閉じて開き直すと押せる状態に戻る(早すぎる再発行はサーバーが429で止めるので、その秒数から数え直す)。回数の値は`backend/docs/mail.md`
  - 応答ごとの表示:

    | 応答 | 表示 |
    |---|---|
    | 再発行の成功 | 「コードを送りました。メールを確認してください」 |
    | `invalid_verification_code` | 入力欄の下に「コードが違います」 |
    | `verification_code_expired` | 「有効期限が切れたか、入力の回数の上限に達しました。コードを再発行してください」 |
    | 再発行で409(`email_already_verified`) | ユーザー情報を取り直して閉じ、スナックバー「メールアドレスは確認済みです」 |
    | 429(`too_many_requests`) | `Retry-After`があれば、その秒数から再発行のボタンのカウントダウンを始める。無ければ「再発行には時間をあけてください」 |
    | 通信できない | 「通信できませんでした」(入力内容は残す) |
    | 確認の成功 | 閉じて、スナックバー「メールアドレスを確認しました」 |

- auth/auth_error_messages.dart: APIのエラー(`code`)を、画面ごとに出すメッセージにする

## widgets/

- recording_phase_banner_view.dart: 収録状態のバナー。保存/破棄が未確定(`stopping`)の間はタップで保存/破棄画面を開き直せる
- location_banner_view.dart: 位置情報のバナー(権限・未取得・更新停止・精度の低下。判定は`frontend/docs/location-tracking.md`)。
  未取得・更新停止では`GpsHelpLinkButton`を付ける
- auth_banner_view.dart: 認証のバナー。再ログインが要るとき(タップでログイン画面)と、メールアドレスが未確認のとき(タップで確認コードの入力画面)に出す。
  ローカルアカウントでは出さない
- gps_help_link.dart: `GpsHelpLinkButton`(「取得のコツ」)。rootのNavigatorで`gps_help_page.dart`を開く
- display_name_dialog.dart: 表示名の入力ダイアログ(表示名の変更・ローカルアカウントの作成で使う)。前後の空白を除いて1〜50文字
- osm_attribution.dart: 地図に重ねるOpenStreetMapのクレジット(`frontend/docs/overview.md`の「地図 (flutter_map)」)
- compass.dart: 地図に重ねるコンパス(`RealCompassWidget`)

## utils/

- save_or_discard_screen.dart: 保存/破棄画面を開く共通の入口`showSaveOrDiscardScreen()`。通常の停止・権限を失ったときの強制停止・起動時の回収の
  全てから`TrackingService`経由で使う(開き方は`frontend/docs/session-recovery.md`の「保存/破棄画面の出し方」)
- delete_conflict_dialog.dart: 他の端末で削除済みの記録をこの端末で編集していたときに、削除を受け入れるか編集内容を残すかを選ばせるダイアログ
  (`docs/design/sync.md`の「削除と編集の競合」)。ダイアログ・スナックバーをUIの外から出すための`navigatorKey`・`scaffoldMessengerKey`もここにある
- duration_format.dart: 経過時間・時刻の表示の共通の書式(`formatElapsedJa`・`formatTimeOfDayJa`)
- elevation_chart_data.dart: 高度のグラフのデータ。横軸は点の順番ではなく`recordedAt`の時間(記録の間隔が不均一でも時間どおりの位置に描く)
- map_tiles.dart: 地図タイルのURLとUser-Agentの設定(`frontend/docs/overview.md`の「地図 (flutter_map)」)
- app_log.dart: 端末のログ`appLog`(`[tag] message`の形。リリースビルドでは出さない)
