# 未完了の収録の回収と保存/破棄画面

アプリのクラッシュ・強制終了(OSによるバックグラウンドのプロセスの回収を含む)で、保存/破棄されないまま残った収録を回収する仕組みと、
保存/破棄画面の設計。2026-11-10時点のmainの実装を正とする。関連: `frontend/lib/services/tracking_service.dart`
(`recoverOrphanedSessions()`・`resumePendingCompletion()`・`completeSession()`)・`views/save_or_discard_page.dart`・
`utils/save_or_discard_screen.dart`・`widgets/recording_phase_banner_view.dart`。

収録中のセッションは`sessions.status = inProgress`でローカルDBに書かれる。一覧(`watchAllSessions()`)と同期(`getUnsyncedSessions()`)は
`inProgress`を除くので、保存/破棄されないまま残ると、一覧にも出ず同期もされずに溜まり続ける。これを検出して必ず保存/破棄させる。

## 回収の流れ

- `RecordingPhase.stopping`を「保存/破棄が未確定」の状態として、通常の停止と回収の両方で使う(回収のための状態は増やさない)
- `MainPage`の`initState`で`recoverOrphanedSessions()`を呼ぶ(ユーザーごとにメイン画面を作り直すので、ユーザーを切り替えるたびにも呼ばれる)。
  収録中なら何もしない
- 今のユーザーの`inProgress`の行を開始時刻の順に取り、`_recoveryQueue`に積んで、先頭の1件を`_session`にして`stopping`にする。
  `completeSession()`で1件決まるたびに、キューが残っていれば`idle`に戻さず、次の1件を`stopping`のまま出す
  - 複数件残ることは「同じユーザーが複数の端末で同時に操作しない」前提では通常起きないが、起きた場合はDBを直接書き換えない限り直せないので、
    キューで1件ずつ処理できるようにしている
- トラックポイントが1件も無い(最初の記録の前に落ちた)収録は、聞かずに破棄する。1件だけの収録は、意味のあるデータ(「ここに行った」という
  1点の記録)として保存/破棄画面に出す
- 「続きから再開」は無く、保存/破棄だけを選ばせる。落ちてから再起動するまでの時間は数秒〜数日と決まらず、収録の開始時のフォールバック
  (15秒)よりも弱い保証しか得られないため。続きは新しい収録として始めてもらう

### 集計値の再計算

収録中の集計値(距離・獲得標高・最高/最低の高度・経過秒数)は、`inProgress`の間はDBに書かないので、残っているトラックポイントから
計算し直す(`_rebuildRecordingSessionFromTrackPoints`)。トラックポイントの一覧が地図の主な内容で、集計値は補助なので、次の誤差は許容する:

- 距離は隣り合う点の水平距離(`Geolocator.distanceBetween`)の合計。収録中の計算にある精度のフィルタ等は再現しない
- 高度が無い点は0として扱う
- 終了時刻は最後のトラックポイントの`recordedAt`。経過秒数は`max(0, 最後のrecordedAt - startedAt)`(開始時刻はフォールバックで
  開始したとき`startedAt`より前になり得るので、負にならないようにする)

## 保存/破棄画面の出し方

- 停止・回収・強制停止で`stopping`になったときは`_presentPendingCompletion()`を通る。収録タブを見ている(または保存/破棄画面が既に開いている)
  なら画面を開き、ほかのタブならスナックバー「保存/破棄が必要なセッションがあります」(「収録画面へ」)を出す
- 後から開き直す入口は`resumePendingCompletion()`に集める。収録タブ以外にいれば収録タブに切り替えてから画面を開く:
  - 収録タブの開始ボタン(`stopping`の間は「前回のセッションを処理」に変わる)
  - 全タブ共通の収録状態のバナー(`stopping`の間はタップできる。画面を×で閉じた後に、ほかのタブから戻る入口になる)
  - 上のスナックバーの「収録画面へ」
  - 通常の停止(`recording_page.dart`は停止した後に`resumePendingCompletion()`を呼ぶ)
- `showSaveOrDiscardScreen()`(`utils/save_or_discard_screen.dart`)は、全画面のルート(`fullscreenDialog`)として開く:
  - 同じ収録の画面が既に開いていれば何もしない
  - 別の収録の画面が開いていて、それが一番上なら`pushReplacement`で差し替える(回収のキューの次の1件)。そうでなければ`push`する
  - 画面を出せない(`navigatorKey`が無い)場合は、データを失わないよう既定の名前・徒歩で保存する

## 保存/破棄画面(`views/save_or_discard_page.dart`)

- 表示は記録の詳細画面に倣う。強制停止・回収の理由(`infoMessage`)は、下に固定した保存/破棄ボタンの上に赤字で出す
- 地図のトラックポイントはDBを`watch`して表示する。通常の停止では画面を開いた後に終了地点が足されることがあり
  (`frontend/docs/location-tracking.md`の「収録の停止と終了地点」)、そのまま地図に出す(表示範囲は最初に合わせたまま動かさない)
- 閉じる(×・戻る)と「後で決める」扱いになり、`stopping`のまま残る。上の入口からいつでも戻れる(どの画面からでも戻れるよう、
  収録タブの中ではなく全画面のルートにしている)
- 破棄は確認ダイアログ「セッション破棄」、保存は名前と移動手段を入れるダイアログ「セッション保存」を挟む。名前の欄は既定の名前
  (選んだ移動手段に合わせて変わる)をヒントとして出し、空欄のまま保存したらその既定の名前にする。移動手段の初期値は徒歩

## 保存/破棄の反映(`completeSession()`)

- DBへの反映を待たずに、先に次の状態(回収のキューの次の1件、または`idle`)に移る。反映を待つ間も`stopping`のままだと、入口から
  決めた後の収録の画面をもう一度開けてしまう(二重に決められる)ため。反映の前にアプリが落ちても`inProgress`のまま残るだけで、
  次の起動で回収される
  - 画面の側は、この呼び出しの中で同期的に差し替えが起きることを前提に、自分がまだ一番上(`isCurrent`)のときだけpopする
- 反映は、終了地点の取得中ならその追加を待ってから行う。保存は端末のDBに書いてから同期(`onUpdateData`)の完了まで待つ。破棄は端末のDBから
  消すだけ(同期済みでない記録なので、サーバーに送るものは無い)
